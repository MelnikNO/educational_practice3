# Лабораторная работа № 2

## Тема: Сравнение теоретических и эмпирических методов исследования 

---
### Работу выполнил: студент 3 курса ИВТ, группы 1.2, Мельник Наталья, 06.04.2026
---

**Цель:** провести сравнительный анализ теоретических и эмпирических методов исследования, применить их на практике для решения конкретной ИТ-задачи, проанализировать преимущества и ограничения каждого из используемых методов

**Задачи:** 
1)	изучить сущность, виды и особенности теоретических и эмпирических методов исследования;
2)	выбрать ИТ задачу и решить её, используя сначала теоретические, затем эмпирические методы;
3)	сравнить результаты, точность, временные затраты и применимость методов;
4)	сформулировать рекомендации по выбору метода для аналогичных задач.

### Этап 1

**Таблица 1 – Теоретические и эмпирические методы: характеристика, примеры применения**

| Метод | Тип (теоретический/эмпирический) | Краткое описание | Пример применения в ИТ |
|----------|--------------------------|--------------------------------|----------------------|
| 1.	Анализ и синтез | теоретический | •	**Описание:** разложение объекта на составные части (анализ) и последующее объединение их в единое целое (синтез) для изучения структуры и взаимосвязей.<br> •	**Преимущества:** позволяет глубоко понять структуру системы, выявить ключевые компоненты и их взаимосвязи.<br> •	**Недостатки:** требует чёткого определения границ анализа, может упустить контекстные факторы. | •	анализ требований к программному продукту перед разработкой;<br> •	разбор архитектуры микросервисов на отдельные компоненты;<br> •	синтез требований из разных отделов в единую спецификацию. |
| 2. Абстрагирование | теоретический | •	**Описание:** отвлечение от несущественных деталей для выделения ключевых свойств.<br> •	**Преимущества:** упрощает сложные концепции, облегчает понимание и реализацию.<br> •	**Недостатки:** потеря части информации может ограничить применимость. | •	абстракция данных в ООП (классы, интерфейсы);<br> •	выделение ключевых метрик для мониторинга системы;<br> •	обобщение паттернов проектирования;<br> •	формирование концептуальных моделей данных. |
| 3. Моделирование | теоретический | •	**Описание:** создание абстрактных моделей для описания и прогнозирования поведения систем.<br> •	**Преимущества:** позволяет тестировать гипотезы без реальных экспериментов, упрощает понимание сложных систем.<br> •	**Недостатки:** упрощение реальности может привести к неточным результатам. | •	моделирование пользовательских сценариев в UX дизайне;<br> •	построение моделей нагрузки на серверы;<br> •	симуляция работы нейронных сетей;<br> •	создание UML диаграмм для описания системы. |
| 4. Классификация | теоретический | •	**Описание:** Распределение объектов, данных или понятий по классам, группам на основе общих существенных признаков.<br> •	**Преимущества:** Упорядочивает информацию; упрощает навигацию и поиск; позволяет выявлять закономерности; основа для таксономий и онтологий.<br> •	**Недостатки:** Жесткость — сложно учесть пограничные случаи; субъективность выбора критерия классификации; требует постоянного обновления при появлении новых типов. | •	**Типы исключений:** Иерархия классов исключений (IOException, SQLException, NullPointerException) для групповой обработки ошибок.<br> •	**Категоризация товаров:** Автоматическое распределение сотен тысяч товаров по категориям интернет-магазина (электроника, одежда, книги) на основе NLP.<br> •	**Уровни логирования:** Классификация сообщений на DEBUG, INFO, WARN, ERROR для фильтрации и мониторинга.<br> •	**Типы серверов:** Группировка железа в дата-центре по ролям |
| 5. Наблюдение | эмпирический | •	**Описание:** систематическая фиксация поведения объектов в естественных условиях.<br> •	**Преимущества:** получение реальных данных, минимальное вмешательство в процесс.<br> •	**Недостатки:** субъективность, трудоёмкость, сложность контроля переменных. | •	наблюдение за поведением пользователей на сайте через веб аналитику;<br> •	мониторинг работы сервера в реальном времени;<br> •	фиксация ошибок при тестировании ПО;<br> •	анализ логов системы для выявления проблем. |
| 6. Эксперимент | эмпирический | •	**Описание:** контролируемое изменение условий для проверки гипотез.<br> •	**Преимущества:** высокая достоверность, возможность установления причинно следственных связей.<br> •	**Недостатки:** затраты времени и ресурсов, сложность воспроизведения в реальных условиях. | •	A/B тест разных вариантов интерфейса;<br> •	сравнение скорости работы двух алгоритмов на тестовых данных;<br> •	нагрузочное тестирование сервера;<br> •	проверка устойчивости системы к сбоям. |
| 7. Опрос | эмпирический | •	**Описание:** сбор информации через анкетирование или интервью.<br> •	**Преимущества:** быстрый сбор большого объёма данных, возможность получить субъективные оценки.<br> •	**Недостатки:** субъективность ответов, низкая достоверность при некорректной выборке. | •	опрос пользователей о удобстве мобильного приложения;<br> •	анкетирование разработчиков о проблемах в процессе работы;<br> •	исследование предпочтений целевой аудитории для нового продукта;<br> •	оценка уровня знаний сотрудников по ИТ направлениям. |

**Вывод:** Теоретические методы применяются в ИТ для проектирования архитектуры, структурирования данных и формализации знаний без вмешательства в реальную систему, позволяя создавать концептуальные модели. Эмпирические методы используются для сбора реальных данных, проверки гипотез и оценки поведения пользователей или системы в действии, обеспечивая практическую достоверность. В комплексе они образуют полный цикл исследования: от идеальной модели до проверки её реальным поведением.

### Этап 2

**Задача:** оптимизация алгоритма сортировки для больших массивов данных.

**Конкретизация:**

•	Массив: 1 000 000 целых чисел (случайные, диапазон 0–1 000 000)

•	Критерий оптимизации: минимальное время выполнения

•	Сравниваются: Пузырьковая сортировка (O(n²)), Быстрая сортировка (O(n log n)), Сортировка слиянием (O(n log n)), Поразрядная сортировка (O(n×k))

**Обоснование выбора теоретических методов**

| Метод | Обоснование | 
|----------|--------------------------|
| Анализ и синтез | Позволяет разложить алгоритмы на элементарные операции (сравнения, обмены, рекурсивные вызовы) и затем синтезировать прогноз времени выполнения через O-нотацию. |
| Абстрагирование | Отвлекаемся от конкретного языка программирования и железа, рассматриваем только алгоритмическую суть — количество операций как функцию от n. |
| Классификация | Разделяем алгоритмы по классам сложности: квадратичные, линейно-логарифмические, линейные — для быстрой предварительной оценки пригодности. |
| Моделирование | Строим теоретическую модель зависимости времени T от размера массива n: T ≈ C × f(n), где f(n) — теоретическая сложность. |

**Обоснование выбора эмпирических методов**

| Метод | Обоснование | 
|----------|--------------------------|
| Эксперимент | Необходимо получить реальные, измеримые значения времени выполнения на конкретном оборудовании, чтобы проверить теоретические прогнозы. |
| Наблюдение | В процессе выполнения фиксируем дополнительные параметры: потребление памяти, стабильность, поведение на граничных случаях. |

**Эмпирический эксперимент**

**Условия эксперимента:**

•	Данные: массив 1 000 000 случайных целых чисел

•	Количество запусков: 5 на алгоритм, берется среднее


**Результаты эксперимента:**

| Алгоритм | Время (сек) | 
|----------|--------------------------|
| Пузырьковая | > 600 (прервано) |
| Быстрая | 2,22 |
| Слиянием | 4,39 |
| Поразрядная | 3,98 |

Результаты не всегда воспроизводимы на других системах. | Методы дополняют друг друга: теория дает направление, эксперимент — точный ответ для конкретных условий. |

### Выводы

1.	Теоретические методы позволили быстро и без затрат ресурсов отсеять заведомо непригодный квадратичный алгоритм и выделить группу кандидатов с приемлемой сложностью O(n log n) и O(n×k).
2.	Эмпирические методы дали точные количественные результаты: быстрая сортировка оказалась быстрее (2,22 сек) против поразрядной (3,98 сек) и сортировки слиянием (4,39 сек), что не следовало напрямую из теоретической O-нотации.
3.	Сравнение показало, что теория точна в грубых категориях («хорошо»/«плохо»), но может ошибаться в тонких различиях между алгоритмами одного класса сложности из-за константных множителей, кэш-эффективности и особенностей реализации.
4.	Теоретический подход существенно менее ресурсоёмкий по сравнению с эмпирическим, но не дает окончательного ответа для конкретной среды исполнения.
5.	Наиболее эффективная стратегия в ИТ-исследованиях — комбинированная: сначала быстрый теоретический анализ для сужения круга кандидатов, затем целенаправленный эксперимент для выбора лучшего решения в реальных условиях.
